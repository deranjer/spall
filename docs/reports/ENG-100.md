# ENG-100 (R7) — Incremental greedy terrain and body meshes

## Implementation

The live client now submits terrain as resident per-brick greedy meshes. Each
cached chunk stores the mesh builder's dependency token; a brick is rebuilt
only when its own revision or a halo dependency changes. Missing neighbors are
recorded as unknown dependencies, so a neighbor arriving invalidates the seam.
Chunks leaving the render radius and chunks that become empty release their GPU
buffers. The rebuild worker no longer generates the legacy terrain cube list;
the public `rebuild_pass` keeps that list for existing instrumentation.

The renderer draws terrain and body meshes through the existing opaque and
shadow pipelines. Terrain mesh buffers persist until a chunk changes. Body
templates are cached by stable body id and topology revision, posed from the
current body transform, and written into reusable dynamic buffers. Mesh AO is
carried through the shared render conversion and multiplies the same skylight
and material lighting as before.

## Evidence

Baseline from ENG-96's whole-volume forest fixture (65,909 exposed cube cells):

| Submission | Triangles | GPU memory | Build time | Frame wall time p50 / p95 |
| --- | ---: | ---: | ---: | ---: |
| Cube instances | 790,908 | 3.0 MiB | 3 ms | 2.47 / 3.19 ms |
| Greedy mesh | 33,972 | 3.0 MiB | 154 ms | 0.30 / 0.65 ms |

These baseline measurements establish the submission choice; the 154 ms mesh
build was a single whole-volume build, not the incremental client path.

On the current machine, the added GPU mesh parity capture and the existing
game/editor parity captures pass with a mean pixel difference of 0.000/255 in
each of five environments. The forest-scale game renderer capture measured
shadow p50/p95 1.4305/2.5405 ms, opaque 0.4639/0.8735 ms, tone map
0.0092/0.0174 ms, and CPU record/submit 1.6244/2.6548 ms. Sky visibility and
shadow acceptance captures also passed, including the sealed-room darkness,
penumbra widening, and contact-shadow checks.

The client cache update path was timed in a debug unit-test run on an 8³ solid
voxel fixture: initial one-brick build 9.057 ms; one-cell edit-to-mesh
9.295 ms, with exactly one brick rebuilt. This small fixture includes the
visible-brick scan, halo freshness check, meshing, and CPU GPU-vertex
conversion. It is a measured functional-fixture latency, not a release
forest-scale target or a live window frame measurement.

CPU checks: `spall_mesh` 39 passed; `spall_client --lib` 48 passed. The mesh
seam test verifies absent-neighbor dependency tracking, neighbor-arrival
invalidation, and seam removal after the adjacent brick becomes resident.

## Limits

The GPU parity capture validates rendering of a resident greedy chunk, but
there is no end-to-end live-window edit capture. The measured 8³ debug fixture
is not representative of a large streamed world; release-scale measurements
remain needed. Bodies use cached topology templates and reusable per-body
buffers, but vertex positions are transformed on the CPU each frame. This is
within the existing client CPU render path; a GPU instance-transform path
remains a possible optimization if profiling warrants it.
