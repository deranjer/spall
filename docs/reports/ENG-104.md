# ENG-104 — Interactive sandbox water demo

Status: local interactive demo implemented. It reuses the existing Spall
client window, shared renderer, and ENG-103 voxel-backed `TwoReservoirFixture`.
Only the explicit demo mode advances fluid on the client; the normal
networked-client path is unchanged.

## Run

From the repository root:

```powershell
cargo run --release -p sandbox --features client --bin sandbox-client -- --fluid-demo
```

The window shows the voxel floor, walls and dam, plus live Salva particle
positions rendered as small blue cubes. Click the window to capture the mouse.

| Input | Action |
| --- | --- |
| WASD | Fly forward/back/left/right |
| Q / E | Fly down/up |
| Mouse | Look around while captured |
| Escape | Release mouse; click the window to capture it again |
| C | Commit the low canal excavation and refresh the voxel boundary |
| B | Commit the dam breach and refresh the voxel boundary |
| Space | Pause/resume fluid stepping |
| R | Rebuild the fixture and reset the experiment |

The HUD reports paused/live status, particle count, starting water volume, and
the latest action result. Simulation uses a fixed 60 Hz step and permits up to
four catch-up steps per rendered frame; it discards excess accumulated time
after that cap so a missed frame cannot trigger an unbounded catch-up loop.

## Checks and limits

- `cargo fmt -p spall_fluid -p spall_client -p sandbox --check` — passed.
- `cargo check -p sandbox --features client --bin sandbox-client` — passed.
- `cargo clippy -p spall_client --lib --no-deps -- -D warnings` — passed.
- `cargo test -p spall_client` — passed, 45 unit tests plus its integration
  suites.
- `cargo run --release -p sandbox --features client --bin sandbox-client -- --help`
  — passed; help lists `--fluid-demo`.
- `cargo run --release -p sandbox --features client --bin sandbox-client -- --fluid-demo`
  — built and launched; the process remained open for interactive use.
- A broader `cargo clippy -p sandbox --features client --bin sandbox-client -- -D warnings`
  was blocked by existing `spall_server` warnings in `serve.rs` (argument
  counts, `clone_on_copy`, and collapsible `if`); those unrelated files were not
  changed here.

This is an opaque, voxel-like particle visualization rather than transparent
water shading. The fluid still runs locally in the client only for this opt-in
playground. It is not part of the server tick, replication, persistence, or
recovery, and it does not resolve ENG-103's scale/performance/stability gates.
The CUA surface in this environment exposed no native app windows, so controls
were not exercised through automated window input after launch.
