# ENG-116 Ecology A evidence

## Scope

This increment adds the CPU-only `spall_ecology` crate and the bounded `ecology-clearing` sandbox scenario. It implements deterministic terrain-aware grass and tree lifecycle state, versioned canonical state encoding and digest, bounded/fair update scheduling, moisture/soil/sky checks, seed-region availability and expiration, immutable growth proposals with terrain and ecology revision dependencies, and acknowledgment-gated growth commits. It also exercises grass harvesting/regrowth, branch damage, root destruction, stale and rejected proposals, and seedling establishment.

The scenario submits accepted wood through the existing `spall_sim::Simulation` edit path. It does not establish server persistence, transaction recovery, network replication, rendering, production serving, or whole-world save/load behavior. Ecology and fixture results are measured below; all performance objectives remain targets until the production workload and platform gates are specified.

## Remaining risks and next work

The scenario uses existing simulation edit requests to demonstrate accepted terrain changes, but does not yet tie ecology acknowledgment to a durable authoritative world transaction or recovery journal. Server persistence, network authority/replication, renderer integration, broader ecology balancing, and representative production performance gates remain unverified. Next unblocked work is server-owned ecology transaction/persistence integration, after its required server/world-store contracts are ready.

The docs mark ENG-113 and ENG-114 as implemented, but their Loopira statuses remain `in_progress`; this increment does not change those tickets or claim they are complete.
