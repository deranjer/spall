# ENG-169 (W5): removal of the grid water solver

Date: 2026-10-11. The stacked-column water is the only water in the engine.
Git history keeps everything removed here.

## Removed

- `spall_fluid`: `grid_mac` (and `grid_mac/`), `component_fluid`, `cut_cell`,
  `phase_graph`, `phase_pressure`, `phase_water`, `phase_fixtures`, `fixtures`,
  the dense `WaterState`, the `grid-fluid-scenario` binary, their tests and the
  seven obsolete examples. Kept: `columns`, `DomainSpec` and `SolidBoundary`
  (the column world can still be built from a boundary, and its tests do).
- `spall_sim`: `water.rs` (`AuthoritativeWater`, `WaterSetup`, growth,
  execution modes), `SimulationConfig::water`, `add_water_region`,
  `restore_water_regions`, `set_water_growth`, the per-tick dense water step,
  `TickReport::water`/`water_regions`. `set_water_spring_rate` and
  `water_spring_rate` now act on the column water.
- `spall_server`: the dense publisher (`water_replication.rs`), the dense
  journal record, `CustomWorld::new_with_water`/`with_additional_water`/
  `water_setup`, the growth log line. The periodic "water frame" status line
  now reports the column water (frame, fluid time, skipped time, step ms,
  active regions, volume).
- `spall_client`: `--grid-fluid-demo` and `--phase-fluid-demo` (and their flags),
  `grid_fluid_demo.rs`, `phase_fluid_demo.rs`, `water_look.rs` (the old keyframe
  mesh), the dense keyframe/delta handling in `net.rs`, and the session's
  dense-water fields. The admin menu's water line now counts replicated column
  regions.
- Sandbox: the coarsening budget and domain box in `worldgen_scene.rs`, the
  dense domain in `editor_scene.rs`, six phase/component/air/geometry probes and
  `water_trench_probe`.

## Tests

Dense-water tests were deleted, not ported, where the column model already
covers the behaviour (`column_water_persistence`, `column_water_replication`,
`tests/column_water.rs`, the buoyancy and swimming tests). Ported to columns:

- worldgen: the plan seeds the arena in open terrain; a player at a spawn stands
  with water running; edits remap only the columns they change (far cuts remap
  none, a cut into the lake bed does, volume is conserved).
- editor valley: the tiered gated spring (now on `ColumnWaterSetup`), the gate
  opening a real passage in the column spans, and the ignored slow flow test
  (water past the wall: closed 0, open 103 cell volumes in 7.6 s).
  The old version seeded water inside the closed tunnel and read the grid; the
  ported one seeds against the closed gate and lets the opening edit wake the
  water, which is how seeded water starts (asleep).

## Checks

`cargo xtask check` passes (fmt, `clippy --workspace --all-targets
--all-features -D warnings`, tests). It was already failing before this ticket
on three unrelated clippy findings (`day_night.rs`, `window.rs::finish_frame`,
`spall_net/tests/transport.rs`); those got a one-line fix or allow each, and
`water_cut_probe.rs` an `.next_back()`.

## Left in place on purpose

- **Wire and storage types for grid water**: `spall_protocol::water`,
  `water_delta`, the `WaterSnapshot`/`WaterDelta` record tags, the checkpoint
  `water` field and the `WaterState` journal payload in `spall_store`. Removing
  them changes the wire and save formats and needs a version decision. The
  server now writes no grid water and the client ignores those records.
  **Recovering a checkpoint that still holds grid water now fails with an
  explicit error** (`persist.rs`) instead of loading without its water.
- `spall_render`'s old water-surface mesh pipeline (`set_water_surface`): the
  client only ever clears it now.
- Historical reports and the ENG-103/105/122 text in `architecture.md` and
  `validation.md`, which now carry a "removed" note.
