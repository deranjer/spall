**Actual stress-lane thresholds** (`fixtures/scenarios/t23-g4-integrated-stress-envelope.json` + defaults). `docs/validation.md` names no numeric stress bound; these are author-chosen and unratified:

- Timing/memory: tick p95 <= 12 ms, p99 <= 16.7 ms, physics p95 <= 6 ms, server peak memory <= 8 GiB (the *normal-lane* provisional targets, applied by `server_timing` defaults; no stress-specific timing target exists).
- Backlog: normal = <= 64 KiB and <= 5,000 ms oldest-message age; age cap 15,000 ms; bytes hard cap 8 MiB; recovery deadline 8 s.
- **Cluster recovery deadline:** for blasts whose commits lie within one recovery window (8 s wall clock) of each other, the deadline is last commit + 8 s. The backlog must be normal in every sample interval starting at or after the deadline and ending before the next cluster's first commit (or window end). With blasts 10 s apart, each cluster is judged over a 2 s span. An interval straddling the deadline is unattributed (`no_evidence`, still fails).
- Egress p95 <= 256 KiB/s per client, baseline rate <= 1 MiB/s, rubble >= 80% of expected edits.

**Verdict dimensions** (session summary `verdict`): hash agreement, workload completion, recovery/reconnect, timing and overall are reported separately; `all_hashes_match` now means hash agreement only. v4-stress: hash agreement pass, workload pass, recovery/reconnect pass, timing **fail**, overall fail.
