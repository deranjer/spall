# G1 CPU-side evidence — ENG-18

Date: 2026-09-09 (cross-brick scene + reordered-snapshot + exact-replay additions)

The tracked `g1-networked-destruction` fixture drives two real `sandbox-client`
OS processes against a real `sandbox-server` over QUIC. It runs on the
**cross-brick** `cross_brick_bridge_scene`: a single column straddling the
`x = 32` brick boundary holds up a beam that also spans both bricks, over an
anchored floor. Client 0 cuts the seam column to detach the beam and both
clients excavate opposite ends of the floor concurrently; client 0 then carves
the falling beam again with a body-targeted cut while it is still moving.

The harness passes only when:

- every one of the ten scripted cuts commits (`transactions_committed >=` the
  cut count — a run that quiesces early therefore fails);
- the server and both clients agree on the final canonical topology hash;
- the detached body's cells were owned **across a brick boundary** — the
  server reports the largest detached body spanning `>= 2` distinct bricks
  (cross-brick structural-support propagation and brick-boundary ownership
  transfer);
- each live client observes the beam move at least
  `minimum_body_displacement_m` (0.3 m);
- the body-targeted cut is accepted against the detached body (that body loses
  solid cells afterwards) on at least one replica;
- the committed topology-event stream, replayed deterministically from the
  tick-0 baseline through the durable journal (`sandbox-server --replay`),
  reproduces the live run's canonical hash.

The `--loss-percent 2` variant additionally requires the live clients to have
observed motion-snapshot datagrams delivered out of `snapshot_seq` order (the
per-client UDP proxy deterministically holds every third server->client
datagram past the 20 Hz snapshot spacing).

Windows 11, rustc 1.96, loopback QUIC, seed 1. `disp` is the largest
straight-line distance a replica saw the detached beam travel; `reorder` is
motion datagrams delivered out of order; `body cut` is whether the client-0
cut against the detached beam removed cells on that replica.

Both runs converge on the same hash, commit all ten transactions, split the
beam into two bodies (the body cut lands), and the tick-0 baseline replay of
the ten committed transactions reproduces that hash. The 2% loss run exercised
reliable retransmission and out-of-order motion delivery; a scripted
`ActionRequest` the server throttled (per-tick admission quota) is now resent
by the client, so the impaired run lands all ten cuts.

Stability: clean run is deterministic. `--loss-percent 2` passed 30 / 30 over
seeds 16001–16030 after the throttle-resend fix (it was ~90 % before).

`body cut` reads `no` on client 1 in both runs: the authoritative body cut
commits on the server and both replicas converge on the post-split hash, but
client 1's replica had not re-observed that specific body between applying the
split transaction and its final snapshot. The gate requires the cut to land on
*some* replica and the hashes to agree, both of which hold.

## Exact-replay mechanism

The harness runs the server with `--save` and `--checkpoint-interval-ticks 0`,
so the world database holds a tick-0 baseline checkpoint plus a journal of
every committed transaction. After the session, `sandbox-server --replay`
opens that database, recovers from the **oldest** checkpoint
(`spall_store::recover_from_base`), replays the entire committed-transaction
journal onto it (`spall_server::persist::replay_from_base_builtin`, the same
`replay_transaction` fold the durable-recovery path uses), and compares the
rebuilt canonical topology hash against the live agreed hash.

## Physics fix (carried from PR #50)

The scenario previously crashed intermittently in Rapier's CCD sweep
(`ccd/sweeps.rs: "No element at index"`) when the terrain collider was rebuilt
on a committed cut. No body in these scenes enables per-body CCD, so the server
runs the built-in scene with the CCD solver pass disabled
(`PhysicsConfig::disable_ccd`). Topology hashes and tick counts are unchanged
with the pass on vs off. The projectile-CCD physics report keeps the pass.

## Scope and remaining gate work

This is CPU-side T11 evidence, not a complete G1 pass. It does **not** yet
cover:

- **Detached beam coming to rest on remaining structure.** With the column
  gone and the terrain collider rebuilt on each cut, the beam keeps falling
  rather than settling on the floor (the pre-existing `late-join-collapse`
  scenario shows the same behaviour). Conservation and hash agreement hold; a
  "body comes to rest" case is tracked as a separate follow-up (it is a
  physics-engine change, not a fixture change).
- **The full gate workload.** No 64 x 32 x 64 m / 60 s / 10-tool-requests-per-
  second run, 4 m sphere cut, 64-brick connected-body stress case, graphical
  clients, captures, or GPU timings; and no measurement against the p95
  commit / split / large-collapse latency targets. Those remain unrun and are
  not represented here.
