# G1 CPU-side evidence — ENG-18

Date: 2026-09-08

The tracked `g1-networked-destruction` fixture exercises two real sandbox OS
clients over QUIC. It cuts the bridge support, performs concurrent terrain
edits, observes detached motion, and requires final server/client topology
hash agreement. The fixture requires at least six committed transactions and
one motion sample per client.

server in each run. The loss run therefore exercised reliable recovery, but it
did not need a brick repair request for this particular cut sequence.

## Scope and remaining gate work

This is CPU-side T11 evidence, not a complete G1 pass. The current sandbox
fixture does not yet provide the full 64 x 32 x 64 m / 60-second / 10-tool-
requests-per-second workload, 64-brick collapse stress case, graphical
clients, captures, or GPU timings. Those remain unrun and are not represented
as passing measurements here.
