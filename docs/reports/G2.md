# G2 graphics gate — evidence (ENG-22 / T15)

This report collects the G2 gate evidence from `docs/validation.md` "G2". It is
delivered in increments, like the G1 gate (`docs/reports/G1.md`); the ticket
stays **in_progress** until every G2 bullet has evidence and an experienced
graphics integrator has reviewed the visual + cost material.

Reference adapter: **NVIDIA GeForce RTX 4080 SUPER, D3D12, pinned `wgpu 24.0.5`**,
debug build. Vulkan is blocked by the ENG-60 native pipeline-creation crash and
is not measured here.

---

## Increment 1 — GPU frame-cost percentiles on the T13/T14 lighting fixtures

**Scope.** A multi-frame GPU cost harness plus the first measured numbers.
`spall_render::capture_frame_series` renders one scene for
`warmup_frames + measured_frames` consecutive frames at a fixed size and
exposure — only the `Shaded` view, i.e. the passes the G2 frame target is
about: indirect trace + denoise, the shadow cascades, one opaque pass, one
tone-map pass — and reduces each pass family's per-frame device time
(timestamp queries) to nearest-rank percentiles (same convention as
`spall_server::commit_latency`). `sandbox-capture --scene g2-frames` drives it
over the existing T13/T14 fixtures at a fixed **1920×1080**, exposure 1.0,
default sun; `docs/validation.md` "G2" names the command.

**What increment 1 does _not_ cover** (increment 2):

- **Exterior daylight terrain** and the **moving-debris / active-collapse**
  scene categories — increment 1 reuses only the still lighting fixtures that
  already exist (`colored_rooms`, `emitter_occlusion_scenes`).
- **At least 120 consecutive _moving_ frames** per scene (camera and/or debris
  motion). Increment 1 renders 120 frames of a _static_ scene to get a device
  cost distribution, not a motion sequence.
- **A persistent-resource client frame loop and the CPU frame budget.** Each
  frame in this harness rebuilds the pipeline and re-uploads the scene, so the
  inner CPU timings are not representative and are not reported. The provisional
  CPU p95 ≤ 4 ms and client p95 ≤ 16.7 ms targets remain unmeasured.
- **Bounded-retrace steady state.** `capture_scene` re-traces the whole 128³
  (2,097,152-cell) lighting cache every frame. A live client re-traces only
  dirty regions (the T14 bounded path, `docs/reports/G2-lighting.md`). The
  numbers below are therefore the **cold full-retrace** cost, an upper bound on
  the per-frame indirect cost, not the amortised client cost.
- **Quality flags** — light leakage, ghosting, noise, shadow instability — and
  the **cell-size decision**. Those need the moving sequences and human review.

### Measured — RTX 4080 SUPER / D3D12, 1920×1080, 10 warm-up + 60 measured frames

`cargo xtask capture --scene g2-frames --output <dir>` (harness defaults).

Shadow, opaque, and tone-map percentiles for the three lower rows track the
`colored_room_open` row (all ≤ ~4 ms p95, ≤ ~9 ms p99); the raster path is not
the concern. A 15 warm-up + 120 measured run gives the same picture (frame-total
p50 ~13–14 ms, p95 ~27–36 ms).

### Findings

1. **The provisional G2 GPU p95 ≤ 12 ms target is missed on the reference
   adapter** — frame-total p95 is 32–38 ms across all four scenes, ~3× over
   target. Even the **median** frame (~12–13 ms) is at or over the 12 ms p95
   target.
2. **The indirect trace pass is the dominant cost** (~10–12 ms p50, up to
   ~25 ms p95) and the largest source of variance. This is the full 128³-cell
   re-trace; a bounded re-trace (T14) touches ~1–3 % of the cache
   (`docs/reports/G2-lighting.md`) and is ~13× cheaper. The gate still needs the
   amortised steady-state number, but the **worst-case cold frame does not fit
   the budget**.
3. **The denoise pass is a secondary cost** (p95 5–12 ms), also running over the
   whole cache every frame.
4. **High frame-to-frame variance** — p50 ~12–13 ms but p95 ~32–38 ms and max
   up to ~48 ms, a ~3× spread. Part of this is the measurement harness —
   per-frame pipeline rebuild and GPU clock gating between discrete
   `capture_scene` calls — and a persistent loop (increment 2) is expected to
   tighten it. It is not yet safe to attribute the tail to the renderer itself;
   a longer 120-frame run showed an even heavier tail on
   `emitter_occlusion_lit` (p99 ~68 ms, max ~88 ms).
5. All four scenes behave alike — the two rooms and the lit/occluded emitter
   sit within ~6 ms of each other at every percentile. Scene content is not the
   variable here; the full-cache re-trace is.

### Provisional cell-size / renderer-direction read (not a decision)

The 128³ cache at `LIGHT_CELL_SIZE_METRES` covers a fixed world box; a full
re-trace of it at 1080p is a ~13 ms GPU pass on a 4080 SUPER. The gate's
freeze decision (terrain/detail sizes + renderer direction) should wait for the
increment-2 evidence — moving sequences, the bounded-retrace steady state, and
the CPU/client frame budget — but increment 1 already establishes that
**a full-cache re-trace cannot be a per-frame cost** at the target resolution;
the renderer must stay on the T14 bounded-dirty-region path, and a periodic
full re-trace (the known limit in `docs/reports/G2-lighting.md`) needs a cost
ceiling of its own.

### Reproduce

```sh
cargo run -p sandbox --features client --bin sandbox-capture -- \
  --scene g2-frames --out .local/runs/g2-frames
# or, through xtask:
cargo xtask capture --scene g2-frames --out .local/runs/g2-frames
```

Exit 3 without a working GPU/driver. `<dir>/summary.json` carries the full
per-pass percentile blocks and the `gpu_p95_target_met` verdict; each scene
subdirectory keeps `first.png` and `last.png` from the measured window.

CPU-only coverage: `spall_render` `capture::tests::frame_stats_*` (nearest-rank
math) and `sandbox-capture` `tests::g2_frame_scenes_are_distinct_lit_and_framed`
(scene set builds, is lit, and is framed). The GPU run itself is manual, like
the other capture evidence.

## Remaining for T15 (increment 2+)

- Exterior daylight-terrain scene + moving-debris / active-collapse scenes.
- ≥ 120 consecutive moving frames per scene category; settled vs moving frame
  comparison.
- Persistent-resource client frame loop; CPU frame-work p95; combined
  client-frame p95 against the 16.7 ms provisional target.
- Bounded-retrace steady-state frame cost (T14 path) vs the cold numbers above.
- Quality flags: leakage, ghosting, noise, shadow instability, per scene.
- Cross-GPU capture + human review; numeric image-diff tolerances.
- The G2 gate freeze decision (terrain/detail cell sizes + renderer direction),
  taken by an experienced graphics integrator on the full evidence.
