# T12 material and direct-light report

Measured 2026-09-08 on Windows 11, NVIDIA GeForce RTX 4080 SUPER, D3D12,
1920×1080, fixed exposure 1.0, four 2048² shadow cascades. Command:

```powershell
cargo xtask capture --output .local/runs/t12-1080p-v3 --width 1920 --height 1080 --strategy greedy
```

The values below are device timestamp-query measurements summed across the six
requested output views. CPU readback and PNG encoding are excluded.

| Fixture | Shadow ms | Opaque ms | Tone map ms | GPU total ms |
| --- | ---: | ---: | ---: | ---: |
| cube | 0.045 | 0.108 | 0.077 | 0.229 |
| tunnel | 0.083 | 0.492 | 0.296 | 0.870 |
| checkerboard | 0.028 | 0.058 | 0.051 | 0.137 |
| negative_corner | 0.027 | 0.268 | 0.181 | 0.476 |
| adjacent_bricks | 0.129 | 0.543 | 0.483 | 1.155 |
| rotated_hollow | 0.182 | 0.770 | 0.616 | 1.569 |

All six stable T05 geometry cameras were visually reviewed. Winding, silhouettes,
the adjacent-brick seam, tunnel/hollow openings, and transformed normals were
correct. The GPU suite verifies that a rotated translated body contributes to
the shadow pass and that the albedo output applies the linear-to-sRGB transfer
exactly once.

The first Vulkan run crashed in the native driver while using the comparison
depth-array path (`STATUS_ACCESS_VIOLATION`). The same workload and all GPU
tests pass on D3D12, which is therefore the Windows default for T12. Vulkan can
still be selected explicitly with `SPALL_WGPU_BACKEND=vulkan` for future
driver/wgpu retesting. This is a backend limitation, not a claimed Vulkan pass.

Indirect illumination, emissive bounce, dynamic dirty-light updates, temporal
stability, and the 120-frame G2 workload are deliberately unrun: T13–T15 own
those gates.
